# Fenpo for Android

Kotlin, Jetpack Compose, Material 3. Decisions and sources: [docs/ANDROID.md](../docs/ANDROID.md). Design: [design/android/android.html](../design/android/android.html).

## Requirements

- JDK 21 (Android Studio's bundled JDK works). Bytecode targets Java 17.
- Android SDK with `platforms/android-37.0` and `build-tools/37.0.0`. Point Gradle at it with `ANDROID_HOME` or an Android Studio generated `local.properties` (not committed).
- Bluetooth needs a real phone; the emulator cannot test it.

## Commands

Run from this folder:

```bash
./gradlew assembleDebug
```

```bash
./gradlew spotlessCheck lintDebug test verifyRoborazziDebug assembleDebug
```

The second command is exactly what CI runs (`.github/workflows/android.yml`).

| Task | What it does |
|---|---|
| `test` | Unit tests: pure JVM modules (`core:protocol`, `core:transport`, `core:pairing`) and Robolectric tests in Android modules |
| `recordRoborazziDebug` | Draws every screen in light and dark, English and Turkish, into `*/src/test/screenshots/` |
| `verifyRoborazziDebug` | Compares the screens against those images; run `recordRoborazziDebug` after an intended UI change and commit the new images |
| `spotlessApply` | Formats Kotlin with ktlint (`ktlint_official`) and the Compose rules |
| `lintDebug` | Android Lint; errors fail the build |

## Layout

| Module | Contents |
|---|---|
| `app` | `MainActivity`, navigation (Navigation 3), manifest, launcher icon |
| `core:protocol` | Types generated by Wire from `../protocol/fenpo/v1/*.proto` |
| `core:transport` | `[uint32 length][Envelope]` framing, TLS 1.3 client with certificate pinning, `Hello` negotiation; test fixtures with an in-process TLS server |
| `core:pairing` | Parser for the `fenpo://pair?...` QR code and the pairing exchange (`PairingRequest` → `PairingResult` → `Hello`) |
| `core:security` | Phone's TLS identity in the Android Keystore, AES-GCM box for stored secrets |
| `core:ble` | GATT client (one operation at a time, MTU, bond, Android 12 and 13+ paths) and the encrypted BLE channel |
| `core:connection` | Companion device association and presence, the `connectedDevice` service, connection state |
| `core:data` | Settings (DataStore), app language, device id and name, paired PC, permission checks |
| `core:designsystem` | `FenpoTheme`, colour roles from the design, icons generated from the design's SVGs, shared components |
| `core:testing` | `captureScreenVariants`: screenshots in both themes and both languages |
| `feature:*` | `home` (home and PC tabs), `pairing` (scanner, steps, permissions), `transfers`, `settings` |

Convention plugins in `build-logic/` hold the shared Gradle setup; versions live in `gradle/libs.versions.toml`.

Instrumented tests (Keystore and TLS, need a phone or emulator): `./gradlew :core:security:connectedDebugAndroidTest`.

## Not done yet

Pairing over Wi‑Fi (QR, TLS, `Hello`) and the BLE channel (companion device association, bond, encrypted and fragmented Envelopes, `connectedDevice` service with presence and heartbeat) are in place and were tried on a Galaxy S10+ with Android 12 (docs/ANDROID.md §21). End-to-end pairing with a real PC waits for the Windows side (S5). Quick actions on the home screen and the feature switches in Settings are stored but not wired to anything yet.

Debug builds have a second launcher entry, **Fenpo BLE probe**, that drives the BLE classes directly for device tests against `spikes/S4-ble-peripheral`.
